Changes save as you make them. Follows your system's light or dark mode.

The extension needs access to all sites to read posts and fetch images.

Posting to Nostr

Right-click a post → Copy post to Nostr, or hover it and press Alt+Shift+N.

Signer

Not connected

Signing uses your NIP-07 extension (Alby, nos2x…). Your key never touches XMRadar.

Relays

Nothing to fill in: XMRadar picks relays for you. Add relays here only to choose your own.

Images

Blossom server for re-uploaded images.

Tags

Tags every copy starts with, separated by commas. Hashtags in the post are added too, and you can change them in the composer.

Tag suggestions

Runs on your computer; nothing is sent elsewhere.

First time? Let the model answer the extension
  1. Get a small model, e.g. ollama pull llama3.2:3b (about 2 GB).
  2. Ollama turns extensions away until you allow them. These steps allow only this extension:
    macOS, in Terminal, then quit and reopen Ollama (run it again after the Mac restarts): launchctl setenv OLLAMA_ORIGINS "chrome-extension://…" Windows, in Command Prompt, then quit and reopen Ollama: setx OLLAMA_ORIGINS "chrome-extension://…" Linux: run sudo systemctl edit ollama, add under [Service], then sudo systemctl restart ollama: Environment="OLLAMA_ORIGINS=chrome-extension://…" Already allow other origins? List them all, separated by commas.
  3. LM Studio instead: start its server and turn on CORS in the server settings.
  4. Click Find local models, then Test.

When you click Suggest, the post's text goes to this provider with your key, and their privacy terms apply. The key stays in this browser: it isn't synced.

With a provider, every copy's text and tags then go to it as you open the composer.

Default tags the post doesn't mention make room for the model's, and stay one click away. Tags you add or remove yourself are left alone.

      Swaps and sites
      
          
      
            On an exchange's order page that carries a signed NKIP-0001 receipt, XMRadar checks it against the key the site publishes, compares the page's addresses with the signed ones, and saves the receipt in this browser only.
            On an order page xmr.club lists with a letter of guarantee, it checks the letter with the operator's key from xmr.club's list the same way.
            Checking contacts only that site. Relays are asked about an order only when you press "Check public record", at least an hour after the order.
          
      
          
      
            
            
          
      
          
      
            
            
            
          
      
          
      
            The only requests are the list itself, from xmr.club, about twice a day, and its logo pack when that changes: the same files for everyone, without cookies or identifiers. The site you're on is matched against it inside your browser and never sent anywhere. The download follows your browser's proxy or Tor settings. xmr.club is run by the same team as XMRadar.
          
      
          
      An export contains your swaps' addresses and salts, and your letters' order ids: anyone with the file can link your deposits to your payouts. Keep it private.
      
          
      
          
          
      
          
      
          
      
          
        
      

        
      
          
      Updates
      
          
      
            XMRadar is installed from a download, so your browser never updates it. It can tell you when a new version is out; you download it from the release page and check it there.
          
      
          
      
          
      
            
            
      
          
      
          
      
            Once a day, or when you click Check now, XMRadar asks xmradar.app for the latest version number. The request carries no version, ID or page; like visiting the site, it shows your IP address and browser, and that XMRadar is in use. It follows your browser's proxy or Tor settings.
